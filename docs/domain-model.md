# Domain Model

MIRROR-X models a software organization's ecosystem through a heavily structured set of domain entities and relationships. Together, these form the **Reality Graph**.

## 1. Domain Entities

### Structural Entities
- **Organization**: The top-level tenant or company.
- **Project**: A logical grouping of repositories and services.
- **Repository**: A version-controlled source code repository.
- **Service**: A deployable software artifact (e.g., microservice, job, frontend).
- **Component**: A modular piece of code within a service.
- **API**: An exposed interface (REST, GraphQL, gRPC).
- **Database**: A data storage system.
- **Table**: A specific structural schema within a database.
- **Dependency**: A third-party or internal library required by a service/component.

### AI & Operations
- **Agent**: An AI entity operating within the ecosystem.
- **Tool**: A function or capability an Agent can invoke.
- **Policy**: A rule governing behavior, permissions, or code standards.
- **Permission**: Specific access rights tied to roles or agents.
- **Environment**: A runtime environment (e.g., Development, Staging, Production).
- **Deployment**: A specific instantiation of a Service in an Environment.

### Lifecycle & Observability
- **Change**: A discrete modification (e.g., a Git commit or PR).
- **Scenario**: A synthetic testing setup or simulation parameter set.
- **TestRun**: An execution instance of a suite or Scenario.
- **AgentRun**: An execution instance of an Agent over a specific trace/session.
- **Evidence**: Ground truth data supporting a Finding (e.g., a line of code, a log entry).
- **Finding**: An analytical conclusion generated by MIRROR-X (e.g., "API drift detected").
- **Release**: A candidate bundle of Changes targeting an Environment.
- **ReleasePassport**: A cryptographic or verifiable artifact certifying a Release passes all Policies.
- **Trace**: A distributed telemetry trace capturing a single request or workflow.
- **MemoryEntry**: A contextual state or historical record retained by an Agent.

## 2. The Reality Graph
The Reality Graph represents the interconnected state of the ecosystem. 

**Nodes**: Repositories, Services, Components, APIs, Databases, Tables, Deployments, Agents, Tools, Policies, Environments.

**Relationships**:
- `contains` (e.g., Repository *contains* Component)
- `depends_on` (e.g., Service A *depends_on* Service B)
- `calls` (e.g., Component *calls* API)
- `reads_from` (e.g., Service *reads_from* Table)
- `writes_to` (e.g., Agent *writes_to* Table)
- `uses` (e.g., Agent *uses* Tool)
- `governed_by` (e.g., Service *governed_by* Policy)
- `deployed_as` (e.g., Service *deployed_as* Deployment)
- `affected_by` (e.g., API *affected_by* Change)
- `validates` (e.g., TestRun *validates* Release)
